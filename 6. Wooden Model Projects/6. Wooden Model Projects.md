# 6. Wooden Model Projects

This chapter is based on the ESP32S3 Xiaozhi AI Chat Robot wooden board and covers four model expansion projects: Rotating Color Light, Environment Monitoring, Automatic Watering, and Smart Trash Bin. Each project is controlled by voice (wake word "你好小智") and programmed with KidsBlock graphical programming.

---

#### 6.1.1 Hardware Connection

| Module | Pin | Note |
|---|---|---|
| RGB module | IO10(rover board: header pin 2) | 4 LEDs |
| Active buzzer | IO3 | Plays notification tones and music |
| Stepper motor IN1 | IO8 | 28BYJ-48 driver |
| Stepper motor IN2 | IO9 | 28BYJ-48 driver |
| Stepper motor IN3 | IO13 (rover board: header pin 48) | 28BYJ-48 driver |
| Stepper motor IN4 | IO14 | 28BYJ-48 driver |

#### 6.1.2 Core Logic

This model registers two MCP tools, which are triggered by voice commands through the AI brain:

1. **musicbox** (boolean state):
   - ON: the stepper motor starts rotating, RGB switches to the rainbow cycle effect, and the buzzer plays the birthday song;
   - OFF: the motor stops, the buzzer stops, and the RGB turns off.
2. **RGB** (brightness + effect):
   - Independently controls the RGB brightness and effect (solid / flashing / breathing / rainbow / flowing / rainbow cycle, etc.).

The stepper motor is timed with `micros()`: it takes one step every 5000 microseconds, and after 2048 steps (half a turn) it automatically reverses, achieving reciprocating rotation instead of using `delay` to block.

| Photoresistor (light) | IO3 (cam board: IO16) | Analog input |

#### 6.2.2 Core Logic

The three sensors are registered as independent MCP tools, and the AI actively reads their values when asked the corresponding questions:

| Tool Name | Function | Return Value |
|---|---|---|
| temp | Reads temperature | Temperature in Celsius |
| light | Reads light | Raw photoresistor value |
| gas | Reads air quality | Raw gas sensor value |

Temperature conversion: analog reading × 3300 ÷ 40950 gives the temperature in Celsius.

#### 6.3.1 Hardware Connection

|---|---|---|
| Pump motor IN1 | IO8 | Motor driver |
| Pump motor IN2 | IO9 | Motor driver |
| Soil moisture sensor | IO3 | Analog input |

#### 6.3.2 Core Logic

Register two MCP tools:

1. **motor** (boolean state): manual watering — true turns the pump on (speed 120), false turns it off.
2. **soil** (boolean state): automatic watering mode — when enabled, it loops to detect soil moisture and automatically turns on the pump for about 4 seconds when the soil is too dry; when disabled, it stops the pump immediately.

Moisture conversion: `(reading - 450) × 100 ÷ 2900`; a value above 80 is judged as dry soil and triggers watering.

#### 6.4.1 Hardware Connection

|---|---|---|
| Servo | IO14 | Open 120°, close 10° |
| Ultrasonic Trig | IO8 | Trigger |

#### 6.4.2 Core Logic

Register two MCP tools:

1. **avoidance** (boolean state): automatic lid-opening mode — true enables it, false disables it. When enabled, it loops to read the ultrasonic sensor; when the distance is less than 10cm, the servo rotates to 120° to open the lid, waits 2 seconds, then rotates to 10° to close it.

![image-20261023161144425](media/image-20261023161144425.png)

2. **servo** (boolean state): manual control — true opens the lid (120°), false closes it (10°).

### 6.5 Summary of Key Points

1. **MCP tools are the "voice entry"**: each peripheral is called by the AI in conversation by registering an MCP tool. The tool name and parameter names must match the code.
2. **Analog sensors vs. actuators**: thermistor, photoresistor, gas, and soil moisture are "read" (analog read); motor, servo, RGB, and buzzer are "write" (output).
3. **Non-blocking control**: use `millis()` / `micros()` timing for the stepper motor and pump delays — do not use `delay()`, or the voice and Wi-Fi will freeze.
4. **The benefit of boolean parameters**: using true/false to represent on/off means the AI can map "打开音乐盒" (turn on the music) to true, keeping the logic simple and clear.
